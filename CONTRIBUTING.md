# Contributing

```sh
npm install
npm run verify
```

`verify` runs, in order: hygiene, fixture pinning, typecheck, lint, tests, build, packaging checks
and a runtime-dependency audit. All of it must pass before anything is pushed.

---

## The public-hygiene rule

**This repository is published.** Nothing in it — source, comments, documentation, test names, error
strings or commit messages — may name any of the following:

- an internal repository or an internal design document;
- a backend commit, source path or symbol;
- a server-side function name;
- the backend's database product, or any internal collection path;
- roadmap phase jargon in any language other than English.

Say **"the Tracive API"** or **"the server"**. Say **"record key"**. Say **"phase 1" / "phase 2"**.

The single allowed exception is the Android application id `com.pleistocent.tracive`, which the
app-presence check genuinely needs, plus this repository's own GitHub path. No other application
id belongs here — a non-production variant appears nowhere in shipping code, so naming one only
discloses that it exists.

`npm run hygiene` enforces this, and it enforces the same thing in CI as it does on your machine.

Its rules come from two tracked places: the shape rules inside `scripts/check-hygiene.js` (commit
ids, infrastructure vendor names, collection-path shapes, the organisation token) and the term list
in `scripts/hygiene-terms.txt`. That list is tracked on purpose. It used to be an untracked
`.hygiene-forbidden`, which meant the forbidden-token category was empty on every CI run — a clean
checkout cannot contain an untracked file — so the category advertised as catching internal
repository names and server-side function names could never fire.

Tracking it does not turn the denylist into the disclosure, because every entry names a shape, a
public framework API, a file-layout convention or a dictionary word of a language. **If you find
yourself wanting to write a real internal name into it, that name belongs in the private list
instead**, and the fact that it cannot be written there is the design working.

Before scanning, the script runs every rule against `scripts/hygiene-selftest.txt` and refuses to
continue unless each one matches its own probe. Adding a rule without a probe fails the build; so
does a rule that has quietly stopped matching anything.

A private, environment-specific list may still be supplied in an untracked `.hygiene-forbidden`
file, one token or `/regex/` per line. It is purely additive: it can only catch more, and its
absence can no longer empty a category.

**What the script does not check: commit messages.** It reads the working tree and never git
history. A CI checkout is shallow by default, so a history scan would silently cover one commit
while appearing to cover all of them, and a message that describes one of these rules trips it.
The rule still applies to commit messages — that part is on the author and the reviewer.

### One deliberate exception inside the code

The shared fixture defines a rejection reason spelled `invalid_document_id`, and that exact string
is preserved because it is the anti-drift contract with the SDKs for Kotlin, Flutter and Swift.
Prose around it says "record key", and the module is `recordKeyGuard.ts`. Do not "fix" the wire
value.

## The grammar fixture is not yours to edit

`test/fixtures/query-grammar-vectors.json` is vendored **byte-identically** into four SDK
repositories, and its expected values were generated by executing the server's own key normalizer.
If your implementation disagrees with a vector, your implementation is wrong.

`npm run fixture:verify` pins it by sha256. It is excluded from Prettier and from ESLint. A grammar
change belongs in the Tracive API first, and then lands in all four SDKs together.

## Things that look like nits and are not

**Do not port the sibling SDKs' string workarounds.** They hand-write character classes in order to
_emulate_ JavaScript string semantics, because the server folds keys that way. This SDK's platform
already _is_ JavaScript: `trim()`, `\s`, `[^0-9]`, `toLowerCase()` and `toUpperCase()` are the
reference behaviour, and reimplementing them would emulate an emulation and add a fresh table to
drift from. The fixture's `crossLanguageSemantics` section says which is which.

The one case-mapping rule that still applies: never `toLocaleLowerCase`, `toLocaleUpperCase` or
`localeCompare`. ESLint makes that fatal inside `src/query/**`.

**Do not use `TextEncoder`, `TextDecoder`, `Buffer`, `btoa`, `atob`, `Array.prototype.at`,
`Array.prototype.findLast` or `Object.groupBy` in `src/`.** Hermes lacks them, and the failure mode
is a crash on exactly the devices least likely to be in a test matrix. ESLint makes these fatal too.
Use the helpers in `src/crypto/`.

**Do not make randomness fall back to `Math.random()`.** Not as a convenience, not behind a flag.
A deterministic PRNG produces predictable PKCE verifiers and predictable GCM nonces while every test
still passes.

**Do not retry a check without an idempotency key.** The SDK cannot tell whether the first attempt
was charged, so a blind retry risks a double charge.

**Do not add a `domain()` query builder.** The Tracive API indexes five identifier types; a domain
key would match nothing, and a miss is still billed.

**Do not add an API key parameter anywhere, in either mode.** A test asserts its absence from the
exported names, from every outgoing request field and header, and from the source itself.

## Differences from the sibling SDKs that are deliberate

Two separate audits have now raised these as findings. They are decisions, and this list exists so a
third does not spend its budget re-deriving them. Anything that differs across the four SDKs and is
**not** on this list is drift, and worth reporting.

- **There is no `close()` here, and Kotlin and Flutter have one.** Theirs release an HTTP connection
  pool that has to be let go of explicitly. `fetch` holds nothing, and `startLinkListener` returns
  its own unsubscribe. A no-op `close()` here would teach a reader that calling it matters.

- **`cacheInitializationError` is Swift-only, and should stay there.** Swift is the only SDK that
  opens a default cache itself and degrades to a no-op one on failure, so it is the only one with a
  failure to report. This SDK surfaces a read fault as `cache_read_failed` instead.

- **`onAuthResult` and `startLinkListener` are React Native-only, and belong here.** Android
  delivers the redirect as an intent and iOS as `onOpenURL`; React Native has neither, so this SDK
  owns the `Linking` subscription instead of the host.

- **The client fronts consent in all four now.** `authorize`, `handleCallback`, `isAuthorized` and
  `clearCache` sit on the client everywhere, delegating to the OAuth flow. Kotlin gained them last;
  they were added rather than removed from the other three because the surface had already shipped
  to partners.

- **A 401 naming something other than the bearer still costs one refresh.** The rule is: the
  terminal codes surface, everything else refreshes once and replays. A hypothetical
  `invalid_api_key` would therefore spend a refresh — which buys nothing, and costs nothing either,
  because there is no API key in this SDK to be invalid and the second 401 surfaces. Narrowing the
  trigger to one exact code is the change that would actually hurt: a bare 401 from a gateway or a
  reverse proxy carries no code at all, and that is the case the rule exists for.

- **The spent-refresh-token history is not persisted.** It dies with the process, on purpose —
  `TraciveOAuth.#spentRefreshTokens` says what that costs (one re-consent after a rolled-back store)
  and why paying it beats writing dead refresh tokens to disk forever.

- **The pending-authorization window is configurable here.** Kotlin and Swift keep theirs private.
  Both shapes are defensible and neither is drift: an integration spanning more than one SDK can set
  the number where it is offered, and cannot make the others disagree with their own constant.

## Tests

No unit test opens a socket, touches a device or launches a browser. Every capability that reaches
the outside world is a port; inject a fake. `src/__tests__/support/` has the ones already written.

The Tracive API is not live, so a test that contacted a real host could only ever be testing
somebody else's DNS.

Coverage floors, enforced in `jest.config.js`: 90% statements on `src/query/**` and `src/cache/**`,
80% overall. The adapter subpaths are excluded from collection because they cannot be loaded without
optional peer dependencies this repository does not install — see
[docs/OPEN_QUESTIONS.md](docs/OPEN_QUESTIONS.md), where they are carried as a named risk rather than
hidden inside a percentage.

## Publishing

First publish is a human action. A scoped package publishes as restricted by default, and
`publishConfig.access` failing silently produces a private package — which is exactly the step that
should not happen unattended.
